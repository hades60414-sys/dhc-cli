# 蒸餾模式（給 AI Agent 讀）

使用者在 DHC CLI 輸入框按了燒杯，這個對話就開著「蒸餾模式」：每一回合的系統提示都會帶一段說明。目的是把使用者做這件工作時的判斷留下紀錄，結案時整理成之後可以重用的知識檔與技能草稿。正事優先，蒸餾紀錄是附帶的，不能拖慢或打斷正事。

## 資料夾

`<工作區根目錄>\蒸餾任務\<專案>\<YYYYMMDD>-<任務名>\`

- 工作區根目錄＝這份 README 所在資料夾的上一層。
- 專案＝這個對話工作目錄（cwd）在工作區根目錄底下的第一層資料夾名；不在工作區底下就用 cwd 最後一層的名稱。
- 任務名用使用者的說法，可以中文，不要有 `\ / : * ? " < > |`。

| 檔案 | 內容 |
|---|---|
| `任務卡.md` | 任務名、專案、cwd、目標（一兩句）、狀態（進行中／已結案）、對話清單（每個對話一行：session id、開始日期、一句話說明） |
| `決策紀錄.md` | 一行一筆，格式見下 |
| `往返\` | 使用者上傳的信件、會議紀錄等原文 |
| `版本.md` | 每交出一版成果記一筆 |
| `結案\` | 結案時才產生 |

## 開始（這個對話還沒對應到任務資料夾時）

1. 取得這個對話的 session id（Claude Code：環境變數 `CLAUDE_CODE_SESSION_ID`）。
2. 在 `蒸餾任務\<專案>\*\任務卡.md` 找這個 id。找到就是接續那個任務，跳過開始步驟。
3. 找不到時，看同一個專案裡狀態是「進行中」的任務卡：這個對話明顯是其中一件工作的延續，就把自己加進那張卡的對話清單；否則開新的任務資料夾、寫任務卡。拿不準就開新的，結案時可以合併。
4. 已經進行一段的對話不用回頭補記，結案時會讀完整對話紀錄。
5. 在這回合回覆的最後用一行告訴使用者：「蒸餾模式：記在〈任務名〉」。之後的回合不要重複這行。

## 工作中（每一回合）

照常把使用者要的事做好。回合結束前檢查這回合有沒有下面的訊號，有就在 `決策紀錄.md` 追加一行：

- 糾正：使用者糾正、否決或退回你的做法或產出
- 選擇：使用者在幾個做法裡挑了一個
- 條件：使用者補了條件、限制、優先順序或範圍
- 理由：使用者說明為什麼，或相關的人在意什麼
- 錯誤：發現的錯誤、重做與根因
- 確認：使用者接受某個做法（「對」「就這樣」也算）

格式：

`- 10/06 14:05 [糾正] <情境一句> → <使用者的決定或原話，引用 20 字內> ｜理由：<使用者說的；沒說就寫「未說明」，不要猜>`

另外：

- 使用者上傳的信件、會議紀錄這類附件，複製一份到 `往返\`，檔名前面加日期。
- 交出一版成果時，在 `版本.md` 追加：日期、版本、交付物路徑、這版改了什麼、為什麼改。
- 不用在回覆裡報告你記了什麼。
- 使用者關掉燒杯後，這個對話就不再記；已經記的保留。

## 結案（使用者說「結案」時）

1. 讀任務卡列出的每個對話紀錄、`決策紀錄.md`、`往返\`、`版本.md`。
2. 在 `結案\` 寫：
   - `知識.md`：這類工作的目標、輸入、步驟、檢核點、常見錯誤，每條附依據（決策紀錄的哪一行）。
   - `skill-草稿\SKILL.md`：可以直接放進 AI Agent 技能資料夾的草稿（frontmatter 有 `name`、`description`，description 寫清楚什麼時候該用）。
   - `待確認.md`：證據不足、互相矛盾或只出現一次的判斷，列給使用者確認。
3. `結案\` 裡的東西要去識別：不寫人名、公司名、主機名、帳號與真實數字，改用角色和佔位字。
4. 任務卡狀態改成「已結案」，回覆使用者三個檔的位置和待確認的題數。

## 規則

- 素材只讀不改；蒸餾的東西只寫進任務資料夾。
- `決策紀錄.md` 與 `往返\` 可以保留原話；`結案\` 一律去識別。
