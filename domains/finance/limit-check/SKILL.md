# 限額檢核

目標：計算各限額的使用率，找出接近或超過限額的項目，依升級路徑回報，並留下完整紀錄。AI 不修改限額、不調整部位，也不建議繞過控制。

## 1. 先確認輸入

- [ ] 限額表版本與生效日期（`<限額表>`），確認是現行有效版本
- [ ] 部位、風險數字的來源與截止時間（`<部位表>`、`<風險來源>`）
- [ ] 限額單位與幣別，與被檢核數字一致
- [ ] 資料品質通過（見 data-quality）。有 STALE 或缺漏，結論要標註

## 2. 限額類型 × 層級

使用率 = 實際值 / 限額。建立矩陣，每格一個使用率：

| 類型 | 說明 | 常見層級 |
|---|---|---|
| 部位 | 名目、市值、淨額、毛額 | 商品、帳簿、交易員、整體 |
| 集中度 | 單一標的、產業、國家、交易對手占比 | 帳簿、整體 |
| 敏感度 | Delta、Vega、DV01 等 | 風險因子、帳簿、整體 |
| 損失 | 單日、當月、累計損失、停損 | 交易員、帳簿、整體 |
| VaR | 風險值限額 | 帳簿、整體 |

層級之間要檢查一致性：下層使用量加總（考慮抵銷規則）不應與上層數字矛盾。上層限額通常也受下層限額約束，任何層級超限都要列出。

## 3. soft / hard 分級

- 使用率達預警水位（例如接近限額的一定比例，水位由風控核定）：預警。
- 超過 soft limit：需通知並說明，通常允許短期存在。
- 超過 hard limit：不得持續，必須依規程處理。
- 水位與分級定義以限額表為準，AI 不自行設定或調整。

## 4. 升級路徑

依限額表或規程所載，通常為：

1. 預警：通知交易員與其直屬主管
2. soft 超限：通知風控與部門主管，要求書面說明
3. hard 超限：立即通知風控主管與高階管理層，依規程限期處置

AI 的職責是正確辨識層級並提供通知內容草稿，實際通知與決策由人執行。

## 5. 超限紀錄欄位

每筆預警或超限都留：

| 欄位 | 說明 |
|---|---|
| 檢核日期與時間 | 含資料截止時間 |
| 限額代號與層級 | 對應限額表 |
| 限額值、實際值、使用率 | 同單位 |
| 分級 | 預警、soft、hard |
| 起始日、持續天數 | 是否為連續超限 |
| 原因判斷 | 市場變動、新增部位、限額調整、資料問題 |
| 證據 | 來源查詢、對應部位列、計算步驟 |
| 通知對象與時間 | 已通知誰、何時 |
| 處置狀態 | 待處理、已說明、已降回、已核准例外 |

## 6. 先排除資料問題

超限結果出現時，先確認不是資料造成：

- 價格過期或錯誤、匯率來源不同
- 部位重複載入、已平倉未扣除
- 限額表版本錯誤、單位不一致

確認是資料問題，仍然要記錄並回報，不可以因此默默略過。

## 7. 不可以做

- 不修改限額值、不修改部位或來源資料
- 不建議拆單、延後入帳、改變分類或其他繞過控制的做法
- 不替人核准例外；例外核准要有授權者的紀錄
- 不用四捨五入把 100.4% 說成 100%

## 8. 產出

- 使用率矩陣（類型 × 層級），超過預警水位的格子標示
- 預警與超限清單，依分級與嚴重程度排序
- 與前一日比較：新增、持續、解除
- 待人工處理事項與應通知對象
