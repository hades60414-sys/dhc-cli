# EOD 日終報表

目標：每天以固定格式產出報表，讓讀者先看到例外，再看細節；每個數字都能追溯來源並通過勾稽。

## 1. 固定格式

每份報表的段落順序不變，沒有內容的段落也保留並寫「無」：

1. 狀態行
2. 摘要（一到三行結論）
3. 例外清單
4. 主表（部位、損益、風險、限額，依報表用途）
5. 與前一日差異說明
6. 附註（資料缺漏、人工調整、待辦）

欄位名稱、單位、小數位數、排序規則都固定。換格式前先通知讀者。

## 2. 狀態行

放在報表最上方，缺一不可：

```
資料截止：<YYYY-MM-DD HH:MM 時區> | 來源：<部位表>、<市價來源> | 完整性：完整／部分缺漏／不完整
```

- 完整性不是「完整」時，緊接著寫缺了什麼、影響哪些數字。
- 任何來源晚到或過期，狀態行要如實反映，不得寫「完整」。
- 有使用 STALE 資料的數字，在主表逐格標註。

## 3. 例外導向

- 讀者最先看到的是例外：超限、break、異常波動、資料缺漏。
- 每個例外一行：項目、數字、門檻、狀態、負責處理的角色。
- 排序：嚴重程度優先，其次金額。
- 例外清單為空時，明寫「本日無例外」，並說明檢查了哪些項目。

## 4. 數字驗證鏈

產出前依序檢查，任一項失敗就在附註回報，不要默默修正：

- [ ] 明細合計 = 小計，小計合計 = 總計
- [ ] 報表總計 = 來源系統的總計（用另一條路徑取數，不要複製同一個查詢）
- [ ] 部位筆數、交易筆數與來源一致
- [ ] 幣別換算使用的匯率與日期有記錄
- [ ] 單位一致（元、千元、百萬元不混用）
- [ ] 損益與部位變動勾稽（見 pnl-recon）
- [ ] 比對前一日報表：期初 = 前一日期末，或差異有說明

## 5. 與前一日差異

- 主要數字都列出 前一日、本日、變動量、變動百分比。
- 變動超過預設門檻的項目，附原因：新交易、平倉、市場變動、資料修正。
- 說不出原因的變動，標為「待確認」，不要編造理由。
- 前一日數字若在事後被更正，註明更正版本與時間。

## 6. 沒有異常也要出報表

- 報表是紀錄，不是警報。沒有例外就出一份「無例外」的報表。
- 沒有出報表的日子，無法證明當天檢查過，因此休市以外的工作日都要產出。
- 資料完全拿不到時，仍出報表，狀態行寫「不完整」，內容只列已知與缺漏項目。

## 7. 不可以做

- 不修改來源資料或手動補數字讓報表平衡
- 不省略例外或把它移到附註
- 不在沒有勾稽的情況下標示「完整」
- 不改動限額或部位

## 8. 交付前最後確認

- 狀態行三個欄位都已填寫
- 勾稽清單全部有結果（通過或已列為例外）
- 檔名含日期與版本，重新產出時遞增版本，不覆蓋舊檔
