# 風險指標覆核

目標：以獨立方式檢查風險指標是否合理、前後系統是否一致。重算時用獨立實作，不照抄待驗系統的邏輯，否則同樣的錯會一起出現。

## 1. 先確認輸入

- [ ] 估值日期、截止時間、合併層級與幣別
- [ ] 部位來源與風險數字來源：`<部位表>`、`<前台風險來源>`、`<風控系統來源>`
- [ ] 市場資料（價格、曲線、波動率）的時效，過期者標示（見 data-quality）
- [ ] 模型版本、參數與情境集版本

## 2. VaR 合理性

- [ ] 方法與參數已記錄：信賴水準、持有期、回看視窗、歷史模擬／參數法／蒙地卡羅
- [ ] 與前一日比較：部位沒大變動時，VaR 不該大幅跳動；跳動需有原因（部位變動、市場資料窗口滑動、參數變更）
- [ ] 加總性：整體 VaR 不應大於各子組合 VaR 之和（一般情形下有分散效果）；違反時檢查相關性或抵銷處理
- [ ] 規模感：VaR 與部位名目、波動度的量級相符（可用「部位 × 波動度 × 乘數」粗估）
- [ ] 零部位或空組合的 VaR 為零
- [ ] 持有期換算（例如單日放大到多日）依該機構規程，不隨意套用

## 3. VaR 回測

- 回測是把每日實際損益與前一日預測的 VaR 比較，統計「損失超過 VaR」的例外次數。
- 在 99% 信賴水準下，約 250 個交易日預期有 2 到 3 次例外。
- 例外次數明顯偏多：模型低估風險。明顯偏少：模型可能過度保守。
- 實際損益與假設損益（部位不變、只有市場變動）要分開回測；前者混入日內交易與費用。
- 每個例外要記錄日期、損失、VaR、主要成因（市場事件、模型缺陷、資料錯誤、部位異動）。
- 例外是否群聚也要看，群聚常表示波動度估計反應太慢。
- 判定門檻（例如分區或失敗檢定）依內部規程，AI 只計算與呈現。

## 4. Greeks 檢查

- [ ] 符號與方向：買進選擇權 Gamma、Vega 為正；多頭股票 Delta 為正
- [ ] 單位一致：Delta 以股數或名目；Vega 以每 1 個波動率點；Theta 以每日
- [ ] 加總：同一風險因子可跨商品加總，不同因子不可直接相加
- [ ] 以有限差分檢查：對標的做小幅上下變動，重新估值，檢驗 Delta、Gamma 是否與報告值接近
- [ ] 到期或深度價內價外商品的 Greeks 是否落在合理邊界

## 5. 壓力測試覆核

- [ ] 情境定義：衝擊幅度、方向、涵蓋的風險因子、是否平行移動
- [ ] 情境版本與核准日期，是否仍符合當前部位性質
- [ ] 衝擊套用是否完整：每個相關風險因子都被衝擊，沒有漏掉的資產類別
- [ ] 結果符號：不利情境下，多頭部位損失、避險部位獲利，方向合理
- [ ] 非線性：幅度放大一倍，損失變化是否合理（含選擇權的凸性）
- [ ] 與歷史重大事件情境的結果量級比較
- [ ] 損失與壓測限額比較（見 limit-check）

## 6. 前台 vs 風控系統一致性

1. 先比輸入：部位清單與筆數、市場資料、匯率、參數是否相同。
2. 再比輸出：同一組合、同一風險因子的 Delta、Vega、VaR 等逐項相減。
3. 差異超過容差時，沿決策順序排查：部位差異 → 市場資料差異 → 模型與參數差異 → 計算方法差異。
4. 兩邊都對不上獨立重算時，兩邊都列為存疑，不要預設其中一邊正確。
5. 差異與原因逐項記錄，附證據；找不到原因者標為未解釋 break。

## 7. 獨立重算

- 用另一份實作（例如 Node.js 腳本）重算抽樣的組合，不閱讀待驗系統的程式碼來複製公式，而是依公開定義與文件另行實作。
- 抽樣要涵蓋：最大部位、最複雜商品、近期變動最大者、歷來出過錯的類型。
- 重算結果與原系統比較，差異在容差內視為通過；不一致時先查自己的實作，再查原系統。
- 重算所用輸入須與原系統同一份快照，否則差異無意義。

## 8. 產出

- 結論：通過／有存疑項目，涉及指標與組合
- VaR、Greeks、壓測的檢查結果表
- 回測例外清單與統計
- 前後系統差異表與根因判斷
- 獨立重算的抽樣範圍、結果與差異

## 9. 不可以做

- 不修改模型、參數、情境或限額
- 不為了讓兩邊一致而調整任何一邊的輸入
- 不用待驗系統的輸出當作驗證自己的依據
