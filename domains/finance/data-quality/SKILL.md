# 資料品質

目標：在任何結論之前，先確認資料可用。品質有問題就標示並回報，不得把有問題的資料悄悄放進結論。

## 1. 五個維度

| 維度 | 問題 | 檢查範例 |
|---|---|---|
| 完整性 | 該有的都有嗎 | 預期筆數與實際筆數；必填欄位空值率；每個部位都有對應價格 |
| 正確性 | 值是對的嗎 | 與獨立來源比對；數值範圍、單位、幣別合理 |
| 時效性 | 夠新嗎 | 資料時間戳與預期截止時間的落差 |
| 一致性 | 不同來源說法一樣嗎 | 前後台部位一致；同一標的在不同表的屬性一致；合計等於明細 |
| 唯一性 | 有沒有重複 | 依業務主鍵檢查重複列；同一筆交易重複載入 |

每個維度都要有明確規則與門檻，寫下來，不靠印象。

## 2. 檢查順序

1. 先查唯一性與完整性（便宜、能抓到載入錯誤）。
2. 再查時效性。
3. 再查一致性與正確性。
4. 最後做異常值檢查。

## 3. Stale price 判定

- 每個價格都要有時間戳與來源。沒有時間戳視為無法判定，不當作新鮮。
- 依資產類別定義容許的延遲（例如交易所上市商品用交易日、流動性低的商品放寬），門檻由資料負責人核定。
- 判定狀態：
  - `FRESH`：在容許延遲內
  - `STALE`：超過容許延遲
  - `MISSING`：沒有價格
  - `OVERRIDDEN`：人工覆蓋，需有覆蓋原因與核准紀錄
- 價格連續多日完全不變，也要列為疑似 stale，特別是正常會波動的商品。
- 停牌、休市、下市造成的不變是合理原因，要查證並註記，不是直接放行。

## 4. STALE 資料不得進結論

- 含 STALE 或 MISSING 價格的部位，其損益、風險、限額結果不得以「正常」呈現。
- 做法：在結果中逐格標註，並在摘要中列出受影響的部位數與金額佔比。
- 影響大到無法下結論時，回報「資料不足，無法判定」，不要用舊價格推估後當成事實。
- 不自行補價、插補或沿用前值。若流程允許使用前值，須是明文規程，且標示為 `OVERRIDDEN`。

## 5. 異常值檢查

規則優先，統計補充：

1. 規則檢查（先做）
   - 值域：價格大於 0、比率在合理區間
   - 單日變動幅度超過該商品的漲跌幅限制或業務合理上限
   - 單位、幣別、小數位數錯誤的典型徵兆（例如價格差 100 或 1000 倍）
   - 買賣價差倒掛、到期日早於估值日
2. 統計補充（後做）
   - 與近期歷史比較的 z-score 或分位數
   - 與同類商品、指數、相關標的的變動比較
   - 統計只用來提示，不單獨作為判定錯誤的依據

異常不等於錯誤。標記後交給人確認，並記錄結果。

## 6. 獨立驗價原則

- 重要價格至少用一個獨立來源驗證：不同供應商、不同系統、或不同取價路徑。
- 獨立指的是來源與取數流程都不同；從同一個供應商的另一張表取數不算。
- 兩個來源差異超過容差，列為價格 break，附兩邊數字與時間戳，不挑對自己有利的一邊。
- 負責產出價格的人不應是唯一驗證的人。

## 7. 產出

- 摘要：整體品質結論（可用／部分可用／不可用）與受影響範圍
- 五維度檢查結果表：規則、門檻、結果、失敗筆數
- STALE／MISSING／OVERRIDDEN 清單
- 異常值清單與人工確認狀態
- 驗價差異清單

## 8. 不可以做

- 不修改來源資料或悄悄補值
- 不因為趕時間而把 STALE 資料當成可用
- 不把統計異常直接斷定為資料錯誤
