# 每日 P&L 調節

目標：確認前台 flash P&L 與後台 actual P&L 一致，差額能被解釋，解釋不了的列為 break 並附證據。AI 只讀資料、計算、回報，不改部位、不改交易、不調整任何來源數字。

## 1. 先確認輸入

- [ ] 估值日期、時區、截止時間一致（flash 與 actual 是否同一個 cut-off）
- [ ] 兩邊的幣別、合併層級（交易員、帳簿、策略、法人）一致
- [ ] 資料來源與版本已記錄：`<flash 來源>`、`<actual 來源>`、`<市價來源>`
- [ ] 資料完整性先過一遍（見 data-quality）。有 STALE 或缺漏的資料，結論要標註

## 2. flash vs actual 比對

1. 以最細的共同層級（帳簿或交易員）逐列相減：`差額 = actual - flash`。
2. 再往上逐層加總，確認各層合計等於下層合計之和。
3. 列出差額絕對值超過容差的項目，依金額由大到小排序。
4. 兩邊有一邊缺列的，單獨列為「缺列」，不要當作 0 吞掉。

## 3. P&L explain

每一筆差額（或每個帳簿的總 P&L）拆成下列成分，並要求加總回到總數：

| 成分 | 說明 |
|---|---|
| 市場變動 | 既有部位因價格、利率、波動率、匯率變動產生的損益 |
| 新交易 | 當日新成交部位的損益（含成交價與收盤價差） |
| 部位變動 | 平倉、部分平倉、移倉、轉帳造成的已實現部分 |
| 費用 | 手續費、交易稅、融資利息、借券費等 |
| 匯率 | 非本位幣部位換算的影響 |
| 模型／參數變更 | 估值模型、曲線、波動率曲面、參數或計價慣例的更動 |
| 未解釋 | 以上都無法說明的殘差 |

規則：

- 未解釋 = 總 P&L - 其他成分之和。它是計算出來的殘差，不是調節用的塞入項。
- 未解釋占總 P&L 的比例過高，視為 explain 失敗，需追查，不能把它直接併入「市場變動」。

## 4. 容差閘門

- 容差由風控或財務主管核定，寫在設定或規程裡，AI 不自行放寬。
- 建議兩層：單筆（帳簿）容差、總額容差。任一層超標就要處理。
- 在容差內：記錄通過，附差額數字。
- 超出容差：進入 break 流程，不得以「金額小」略過。
- 容差內的差額若連續多日同方向，也要提出，可能是系統性偏誤。

## 5. break 根因決策樹

依序排除，找到即停，並附證據：

1. 資料面：任一邊缺資料、重複載入、截止時間不同？
2. 價格面：市價來源不同、價格過期、收盤價取值規則不同？
3. 交易面：交易漏進或重複進、取消更正未同步、交易日與結算日混用？
4. 部位面：部位數量或單位不同、公司行動（配股配息、分割、減資）未套用？
5. 匯率面：匯率來源、取值時間不同？
6. 模型面：模型版本、曲線、參數、計價慣例不同？
7. 費用與應計：費用、利息、應計項目口徑不同？
8. 仍無法解釋：標記為「未解釋 break」，轉人工，附完整比對底稿。

## 6. 紀錄四要素

每個 break 與每次調節都要留：

| 要素 | 內容 |
|---|---|
| 誰 | 執行者與覆核者（人或工具名稱） |
| 何時 | 估值日期、執行時間、資料截止時間 |
| 數字 | flash、actual、差額、各成分金額、容差 |
| 證據 | 來源檔或查詢、兩邊對應的原始列、計算步驟 |

## 7. 不可以做

- 不為了讓差額歸零而調整任一邊的數字
- 不把未解釋的殘差歸到「其他」就結案
- 不修改部位、交易或估值參數
- 不在資料有 STALE 標記時宣稱調節通過

## 8. 產出

- 一行結論：通過／有 break，涉及金額與帳簿數
- 差額表（依金額排序）
- P&L explain 表
- break 清單，含根因判斷與證據；未解釋者另列
- 待人工處理的事項與建議的下一步
